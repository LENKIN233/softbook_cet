# PC Web Core Surface Rejected Patterns v1

## Source

`docs/design/search-runs/2026-08-01-pc-web-core/`

## Rejected Patterns

### Dashboard-first width

Do not use desktop width to make progress, schedules, charts, counters, or recent activity the first read. Statistics remains a quiet supporting route; Learning remains the product center.

### Multi-card study grid

Do not present several cards or modules as equal primary choices. The default Learning route has one system-sequenced current card and one primary interaction.

### Floating application windows

Do not model knowledge space as draggable application windows. Window placement is arbitrary desktop organization and cannot represent library / group / box / card ownership, favorite tags, or sleep/wake state.

### Module catalogue as home

Do not turn the seven libraries into a course catalogue or default navigation tree. Hierarchy becomes fully visible on Space; Learning only shows a compact address aperture.

## Reuse Boundary

Charts, grids, windows, and catalogues are not universally forbidden UI primitives. They are rejected as the first-read PC Web grammar for this product. A later artifact may use a bounded grid or table only when its product owner explicitly requires that shape and it does not displace the current learning object or physical Space hierarchy.
