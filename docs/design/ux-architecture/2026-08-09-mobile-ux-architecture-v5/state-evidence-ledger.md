# Mobile UX Architecture v5 — State Evidence Ledger

## Status boundary

- Ledger state count: 160 semantic states plus 13 forced cross-state combinations: the parent's 141 states, nine explicit lightweight check-in states, and ten rows created by splitting compound evidence obligations.
- The parent platform counts are retired. Against the corrected frozen hashes in `browser-evidence.md`, conservative exact browser coverage is now iOS phone `38`, Android phone `10`, iPadOS `8`, Android tablet `8`, and shared access-profile browser `12`. A further iOS `14`, Android phone `5`, iPadOS `5`, and Android tablet `5` states were visibly operated but remain `observed_browser_presentation_only` because the design adapter cannot prove their canonical origin or commit truth.
- The contract transcript is complete enough to review each state’s authority, origin, return target, learner intent, action, commit truth, and recovery.
- All rendered and target columns are fail-closed. They start blocked and may change only after exact evidence is recorded in `browser-evidence.md` or a separately accepted target artifact.
- Formal-commerce and managed-access rows use physically separate shared browser documents operated at phone and tablet widths; their browser cells prove only shared learner semantics and responsive containment, never OS integration, store behavior, receiver operations, or native capability.
- `covered_exact_transcript` is architecture text evidence only. It is never browser, native, store, audio, service, or release evidence.
- `blocked_not_rendered`, `blocked_native`, and `blocked_pc_web_mapping` are deliberate gate failures, not omissions.

## Result terms

| Result | Meaning |
| --- | --- |
| `covered_exact_transcript` | The exact state row exists in the contract and passed semantic review. |
| `covered_browser_scenario` | The exact learner state was rendered and operated in the named platform browser-framed document; it remains non-native. |
| `covered_shared_browser_scenario` | The exact state was rendered and operated only in a physically separate generic access-profile browser document; it is not a platform cell. |
| `observed_browser_presentation_only` | The proposed learner presentation was visibly operated, but the row remains blocked because its canonical origin, acknowledgement, durability, or refresh truth was not proved. It is excluded from coverage counts. |
| `blocked_not_rendered` | No exact learner rendering/operation has been recorded for this device class or shared proof class. |
| `blocked_not_replayed` | The source changed after the prior frozen replay; the current exact bytes have not yet earned this device-class cell. |
| `blocked_partial_scenario` | Some branches or layout were observed, but the complete state row was not proved; partial presence is not coverage. |
| `blocked_origin_unproven` | A learner-like pending/error surface exists, but the contract's required origin or external confirmation was not established. |
| `failed_browser_scenario` | The recorded exact browser behavior contradicted the state contract; the cell remains failed until a corrected exact-source replay is recorded. |
| `blocked_native` | No accepted real-device/native evidence exists. |
| `blocked_pc_web_mapping` | No exact current-state pointer to the accepted PC Web authority/evidence has been recorded. |
| `not_applicable_with_authority` | Only valid with a cited owner that makes the state inapplicable; none are assumed by default. |

A shared access-profile browser result belongs only to the physically separate generic formal-commerce or managed-access document. It cannot be copied into an iOS, Android, iPadOS, or Android-tablet cell and proves no OS composition, system store, native bridge, or canonical service outcome.

For a service-backed row, `covered_browser_scenario` proves only the proposed learner-facing presentation and transition reached by the design adapter. It does not prove the canonical service origin, durability, or reconciliation named in the contract. High-risk access/store states whose defining origin is absent, including `MEM-02` and `BUY-02`, remain explicitly blocked rather than receiving presentation-only coverage.
