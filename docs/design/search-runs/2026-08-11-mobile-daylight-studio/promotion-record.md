# Daylight Studio Promotion Record

## Promoted Artifact

`candidate-proofs/sbv-09-daylight-studio.html` is promoted as the accepted learner-facing visual baseline; `candidate-proofs/sbv-09-interaction-atlas.html` is its required interaction companion.

## Winning Candidate

sbv-09 Daylight Studio.

## Baseline Comparison

Unlike rejected `mvr-15`, the winner does not use pale grey/white as the theme, a spine/address gimmick, cut-corner stationery, review cockpit, or leaked implementation language. It uses stable violet brand chrome, the canonical index-1 coral identity for this exact sample, opaque white task surfaces, real CET copy, one primary action, and explicit phone/tablet/desktop composition. Coral is not reassigned to whichever hall becomes current. It also corrects the current runtime UI's hierarchy and overflow without treating that runtime as design authority.

## Borrowed Fragments

- sbv-01: immediate brand → task → answer → action read order.
- sbv-02: continuous task plane, inline result, and low container count.
- sbv-03: broad tablet workspace and bounded desktop rail.
- historical interaction evidence only: answer → analysis → continuation and vertical lock progression, without borrowing rejected palettes or metaphors.

## Rejected Fragments

Monochrome wireframes, paper/editorial stacks, glass/aurora blur, poster grids, architectural Space-first shells, target/reel graphics, universal pills, black primary actions, palette-only state, and any reviewer/prompt/spec/debug text on learner screens.

A separate post-merge implementation PR must map shared tokens and app chrome, Learning multiple-choice/flip states, five interaction-family components, Space hierarchy and continuity, Statistics, Mine/Auth, membership sheets, safe areas, tablet/desktop composition, focus, reduced motion, and semantic labels. No RN code may reinterpret the palette or layout in the design-only PR.

## Unimplemented Gaps

This design-only promotion is not native implementation evidence. Real iOS and Android font metrics, keyboard/IME, VoiceOver/TalkBack, gesture physics, offline/async recovery, native purchase sheets, device rotation, and release builds remain mandatory Phase B gates. The development fixture copy is not formal approved content.

## Design Review Checklist Answers

Q1: The current CET task is the only dominant focal object; progress, navigation, and location stay visually subordinate.
Q2: Each state exposes exactly one next primary action and keeps browse/history secondary.
Q3: Selection, correctness, favorite, sleep, assessment, auth, and membership use text and geometry in addition to color.
Q4: The winner avoids every recorded forbidden family and does not recreate `mvr-15` under a new palette.
Q5: Phone, tablet, desktop, safe-area, narrow-width, and reduced-motion strategies are explicit and renderable.
Q6: AP-22 Learning↔Space continuity is visible; VL-AP-07/AP-23 preserves exactly mint “有把握” and amber “再回看”, never red or four levels.
