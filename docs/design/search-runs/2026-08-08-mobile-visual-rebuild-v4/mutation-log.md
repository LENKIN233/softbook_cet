# Mobile Visual Rebuild V4 — Mutation Log

## Generation

Source: rejected v3 direction plus the withdrawn first v4 shared-DOM revision.
Target: eight physically separate exact learner documents and a reviewer-only
gallery. There is no shortlist leader or promoted synthesis.

## Product Truth And Implementation Hypothesis

Interaction meanings, feedback truth, Space hierarchy, top-level order, and Auth
continuity are `product_truth`. The eight rendered visual systems and every
proposed synthesis fragment remain `implementation_hypothesis`.

## Failure Signal

Users reported severe visual quality failure, abnormal color, overflow, weak
interaction design, and internal language appearing in a screen that looked like
the product. Independent review then found shared DOM skins, false-positive flip
feedback, missing next behavior, static Space, broken Auth history, and missing
interaction families.

## Targeted Mutation

Create eight independent learner DOMs; isolate the reviewer gallery; implement
all five truthful interaction loops; add real swipe drag plus labeled button
alternatives; preserve explicit empty/incorrect feedback and one committed CTA;
make Space and Auth operable; and verify responsive browser floors.

## Expected Improvement

The learner should recognize the current task and next action before brand
chrome. Feedback should describe what actually happened, and reviewer/process
content should have no dependency path into learner documents.

## Risk

Structural truth can pass while visual quality remains generic. Shared runtime
behavior can hide shared P1 omissions: weak platform icons/differences, absent
causal motion, incomplete Auth/Space pending-error-retry states, partial library
deep links, under-resolved tablet composition, and non-production audio.

## Result

The mutation closed the earlier truthfulness and basic operability defects at
browser-proof level. Swipe now supports real dragging; empty and incorrect
submissions are explicit; committed results keep one strongest next action; and
the eight learner DOMs are physically separate. `speechSynthesis` remains a
design-proof convenience, not a formal audio asset. Final browser terminal
testing passed for all eight iOS- and Android-framed 390 × 844 states with no
horizontal overflow, primary CTA clear of navigation, 44px iOS / 48px Android
active-control floors, and 2 × 2 multiple choice. The mvn-08 1024 × 768 tablet
Lock CTA remained in the first viewport at y=671–719 on iOS and y=689–737 on
Android. Native safe-area, IME, VoiceOver/TalkBack, physical-device, and real
native 200% text verification remain open.

All eight candidates remain blocked from advancement by the shared P1 gaps in
`strict-review.md`. No candidate, score, ranking, earlier leader, or combined
candidate skeleton is carried forward. The next architecture keeps only
candidate-independent requirements—reachable phone action, legible Space
ownership, conditional tablet context, and readable four-choice/body rhythm—
and must derive new geometry rather than trace any v4 document.
