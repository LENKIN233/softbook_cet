# Pairwise Review: pcw-02 vs pcw-03

## Pair

- Candidate A: `pcw-02`
- Candidate B: `pcw-03`

## Reviewer Role

Cross-functional review covering product truth, task clarity, visual language, motion, physical-space continuity, implementation mapping, and accessible layout.

## Winner

Candidate A, `pcw-02`.

## Visual Evidence

- Candidate A: `candidate-proofs/pc-web-candidate-proof.html#pcw-02`
- Candidate B: `candidate-proofs/pc-web-candidate-proof.html#pcw-03`

## Product Truth

`pcw-03` is the stronger Space model, but the whole app must keep Learning as the primary promise. `pcw-02` protects current-card authority more consistently.

## Task Clarity

`pcw-02` begins with one exam task. `pcw-03` makes the learner read hierarchy and box state before reaching the operation.

## Space Or Interaction Fit

`pcw-03` clearly wins for Space hierarchy and state placement. `pcw-02` wins for the Learning and review flow. The synthesis should use `pcw-03` only when the route is Space or when Learning needs a compact address aperture.

## Visual System Fit

Both preserve Law of One. `pcw-03` carries a greater risk of other library colors gaining visual weight in the tree.

## Implementation Mapping

`pcw-02` maps simply to one current object and attached state. `pcw-03` maps well to the Space route but should not define the general Learning shell.

## Rationale

Choose `pcw-02` in this pair because system-sequenced Learning remains the strongest entry. Harvest `pcw-03`'s tree / box / inspector composition for the dedicated Space frame.

## Borrowable Fragments

- `pcw-03`: explicit parent shelf, current box, contained cards, and sleep alcove.
- `pcw-02`: trusted exam-object treatment and attached resolution.

## Rejected Fragments

- `pcw-03`: persistent expanded hierarchy on every Learning state.
