# PC Web Core Hard Filter Results

## Filter Scope

Generation 1 for the 1440 x 900 PC Web core application. The accepted baseline is the platform layout decision plus the mobile object grammar, Learning interaction artifacts, and Space physical model. Filters cover system sequencing, single focal object, Law of One, all five interaction silhouettes, physical Space hierarchy, quiet Statistics and Mine, membership context, keyboard equivalence, forbidden patterns, desktop containment, and design-only authority.

## Rejected Candidates

- `pcw-05`: rejected because progress charts, schedule, and counters displace the current knowledge card and turn the app into a management dashboard.
- `pcw-06`: rejected because six equal card/module tiles make the learner choose the next task and erase interaction-specific silhouettes.
- `pcw-07`: rejected because movable floating windows create arbitrary layout management, unstable focus order, and a false equivalence between desktop position and knowledge ownership.
- `pcw-08`: rejected because the seven-library catalogue makes module selection the primary path and flattens physical Space into navigation.

## Surviving Candidates

- `pcw-01`: passed current-object dominance, three-rail desktop adaptation, single-card sequencing, address continuity, Law of One, keyboard annotation, and containment.
- `pcw-02`: passed exam trust, current-object continuity, attached review state, Law of One, and containment; document-reader drift remains a soft risk.
- `pcw-03`: passed visible library / group / box / card hierarchy, favorite-tag and sleep-zone semantics, Law of One, and containment; Space dominance remains a soft risk.
- `pcw-04`: passed keyboard equivalence, primary-action clarity, canonical silhouette discipline, Law of One, and containment; generic utility tone remains a soft risk.

## Product Truth Violations

`pcw-05` violates Learning priority and user-cost minimization. `pcw-06` violates system sequencing and interaction silhouettes. `pcw-07` invents arbitrary organization and replaces product state with window state. `pcw-08` makes module browsing the product center and misrepresents hierarchy as a catalogue.

## Layout Or Proof Violations

All eight candidates are rendered in `candidate-proofs/pc-web-candidate-proof.html`. `pcw-05` and `pcw-06` are visually contained but too dense. `pcw-07` deliberately overlaps regions and cannot guarantee stable focus or bounded content. `pcw-08` is contained but uses width to multiply equal choices.

## Notes For Mutation

- Keep `pcw-01`'s stable left route rail, dominant current object, and bounded right context rail.
- Borrow `pcw-02`'s attached exam-material slip without adopting a document-reader shell.
- Borrow `pcw-03`'s explicit hierarchy only on Space and as a compact address aperture on Learning.
- Borrow `pcw-04`'s keyboard focus discipline and discrete reduced-motion fallback.
- Reject dashboard, multi-card, floating-window, and catalogue-first structures from the promoted synthesis.
