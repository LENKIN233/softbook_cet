# PC Web Candidate: Module Library

## Candidate ID

`pcw-08`

## Provenance

- Tool or model: Codex negative-direction composition.
- Prompt: Make the seven libraries and their modules the primary desktop navigation surface.
- Source context pack: `../context-pack.md`.
- Artifact: `candidate-proofs/pc-web-candidate-proof.html#pcw-08`.
- Screenshots: `candidate-proofs/pc-web-candidate-proof.html#pcw-08`.

## Product Truth Fit

Fails because library and module selection becomes the product center; the guided current-card path becomes a secondary detail route.

## Focal Object

The library catalogue rather than the current knowledge object.

## First-Read Path

Library list -> group list -> box list -> card, reversing the intended Learning priority.

## Interaction Silhouette

No core interaction is visible until after several selections.

## Spatial Model

Hierarchy is visible but expressed as catalogue navigation rather than a physical map with current object and supported states.

## State Language

Favorite and sleep become filters or folders.

## Motion Causality

Navigation expansion reflects catalogue browsing, not knowledge-object operations.

## Platform Strategy

Uses a familiar desktop information architecture that conflicts with the product's low-cost guidance.

## Implementation Mapping

Would invert route priority and create a module-first application shell.

## Known Risks

- Generic course catalogue.
- High choice burden.
- Physical-space semantics flatten into navigation.

## Design Review Checklist Answers

Q1: Seven library colors gain equal weight; fail.

Q2: Catalogue is focal, not the current card.

Q3: Learning silhouettes are absent; Space becomes navigation.

Q4: No specific forbidden visual token, but product drift is decisive.

Q5: Contained but structurally wrong.

Q6: Module selection becomes primary; rejected.
