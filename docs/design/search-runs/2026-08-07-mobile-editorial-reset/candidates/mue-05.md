# Resume Dashboard

## Candidate ID

mue-05

## Provenance

- Tool or model: Codex design synthesis
- Prompt: Start the app with today summary, streak, review counts, and a resume card.
- Source context pack: `context-pack.md`
- Artifact: No-render rationale: dashboard-first composition violates the system-sequenced single-card focus.
- Screenshots: No-render rationale: the product-truth failure is structural, not visual polish.

## Product Truth Fit

Fails because statistics and planning become the first task instead of the current CET card.

## Focal Object

A today-summary dashboard.

## First-Read Path

Counts → status → resume CTA → card, which is the wrong order.

## Interaction Silhouette

No core card interaction is visually identifiable on the first screen.

## Spatial Model

Space becomes a dashboard shortcut with no hierarchy.

## State Language

Progress metrics dominate learning feedback.

## Motion Causality

Metric animation would describe reporting rather than card state.

## Platform Strategy

Dashboard grids scale easily but preserve the wrong information architecture.

## Implementation Mapping

Would require elevating Statistics into Learning, contradicting current route ownership.

## Known Risks

High cognitive burden, gamification drift, and loss of CET-card focus.

## Design Review Checklist Answers

Q1: Library color loses authority to metric colors.

Q2: The focal object is wrong by construction.

Q3: No canonical Learning silhouette survives.

Q4: Metric chrome risks forbidden gamification.

Q5: Layout could fit, but the primary task would not.

Q6: Learning would expose planning before the system-selected card.
