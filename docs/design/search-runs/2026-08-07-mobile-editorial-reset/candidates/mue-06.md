# Full-Bleed Library Color

## Candidate ID

mue-06

## Provenance

- Tool or model: Codex design synthesis
- Prompt: Use the current library color across the entire phone and float cream study content above it.
- Source context pack: `context-pack.md`
- Artifact: No-render rationale: full-screen coral fails quietness and creates avoidable contrast risk.
- Screenshots: No-render rationale: hard filter rejected decorative color weight above the Law-of-One intent.

## Product Truth Fit

Maintains one hue but mistakes “one dominant accent” for “fill most of the viewport.”

## Focal Object

The color field becomes focal instead of the CET card.

## First-Read Path

Color field → floating content → controls, creating visual noise before meaning.

## Interaction Silhouette

Card shape remains visible but loses authority against the page field.

## Spatial Model

Space location is reduced to a floating label.

## State Language

Library identity overwhelms correctness and self-assess semantics.

## Motion Causality

Color transitions would be route decoration rather than object-state motion.

## Platform Strategy

Large color fields become more oppressive on tablet.

## Implementation Mapping

Technically simple token mapping but hard to maintain accessible contrast.

## Known Risks

Fatigue, loudness, and reduced content legibility.

## Design Review Checklist Answers

Q1: One hue is used but at excessive visual weight.

Q2: The page color displaces the card as focal object.

Q3: Interaction silhouettes are weakened by the surround.

Q4: No literal blocklist token is required, yet quietness fails.

Q5: Containment is possible; contrast is not reliably safe.

Q6: Flip semantics could remain correct, but the direction is rejected earlier.
