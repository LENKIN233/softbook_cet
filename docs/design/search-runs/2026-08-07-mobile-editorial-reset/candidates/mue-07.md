# Study Timeline

## Candidate ID

mue-07

## Provenance

- Tool or model: Codex design synthesis
- Prompt: Visualize the five-card round as a vertical study timeline with the current card expanded.
- Source context pack: `context-pack.md`
- Artifact: No-render rationale: visible sequencing makes the user manage progress instead of following the current card.
- Screenshots: No-render rationale: the timeline violates the low-operation learning contract.

## Product Truth Fit

Fails because system sequencing becomes visible management chrome.

## Focal Object

The round timeline competes with the current card.

## First-Read Path

Past cards → current node → future nodes → operation, delaying the task.

## Interaction Silhouette

The current card is compressed into a timeline node and cannot retain its canonical shape.

## Spatial Model

Timeline position is mistaken for physical knowledge-space position.

## State Language

Completed/pending states dominate exam understanding.

## Motion Causality

Timeline advancement emphasizes progress management rather than card understanding.

## Platform Strategy

Scales as a sidebar on tablet but remains the wrong product model.

## Implementation Mapping

Would add a new high-weight round-state surface not owned by the Learning contract.

## Known Risks

Management burden, dashboard drift, and Space semantic confusion.

## Design Review Checklist Answers

Q1: Accent would be split across multiple timeline nodes.

Q2: The timeline, not the card, becomes focal.

Q3: The canonical card silhouette is lost.

Q4: Progress chrome approaches gamification.

Q5: A timeline can fit only by shrinking the task.

Q6: System sequencing becomes a visible module-like path.
