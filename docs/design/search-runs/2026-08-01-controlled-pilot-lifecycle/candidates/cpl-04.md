# DesignCandidate: Trial Timeline Dashboard

## Candidate ID

`cpl-04`

## Provenance

- Tool or model: Codex design search.
- Prompt: Show all five days, remaining time, daily progress, and entitlement in one lifecycle home.
- Source context pack: `docs/design/search-runs/2026-08-01-controlled-pilot-lifecycle/context-pack.md`
- Artifact: prose-only rejected record.
- Screenshots: No-render rationale: dashboard-first hierarchy violates the Learning-first and no-complex-statistics hard filters.

## Product Truth Fit

Fails by making time and counters the product center and by implying local calculation authority.

## Focal Object

A countdown dashboard, which is the wrong object.

## First-Read Path

Countdown -> day panels -> progress -> Learning.

## Interaction Silhouette

Management dashboard rather than single-card flow.

## Spatial Model

Space becomes a secondary link with no physical continuity.

## State Language

Urgent time and completion metrics dominate.

## Motion Causality

Ticking countdown is decorative and anxiety-producing.

## Platform Strategy

Would scale as a dashboard, which remains out of scope on every platform.

## Implementation Mapping

No mapping; it invents a local lifecycle computation surface.

## Known Risks

Anxiety, false precision, entitlement disagreement, and feature creep.

## Design Review Checklist Answers

Q1: Multiple semantic colors would compete.

Q2: Wrong focal object.

Q3: Learning and Space silhouettes fail.

Q4: Complex statistics and reward-like progress are forbidden.

Q5: Not rendered after hard-filter rejection.

Q6: No self-assess change.
